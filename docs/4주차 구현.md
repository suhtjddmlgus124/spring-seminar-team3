# 4주차 구현 정리

## 발생할 수 있는 문제

정원이 30명이고 현재 29명이 신청한 상황에서 두 요청이 동시에
인원을 조회하면 두 요청 모두 신청할 수 있다고 판단할 수 있다.
이후 두 신청을 모두 저장하면 정원을 초과한다.

같은 사용자의 신청 요청이 동시에 들어오면 중복 확인을 모두 통과할
수 있다. 취소도 조회와 삭제가 따로 실행되면 같은 신청을 여러 요청이
삭제하려고 할 수 있다.

출석과 과제 기록을 여러 건 수정할 때는 앞의 저장이 끝난 뒤
다음 저장에서 실패할 수 있다. 이때 앞의 변경만 남으면 요청이
일부만 반영된다.

## 해결 방법과 선택 이유

### 세미나 행의 비관적 락

신청과 취소는 같은 세미나 행을 SELECT FOR UPDATE로 조회한 뒤 처리한다.
앞선 요청이 끝나면 다음 요청이 락을 얻어 현재 신청 내역을 확인한다.

운영 정보와 출석·과제 기록 수정도 같은 세미나 행을 먼저 잠근다.
취소와 기록 수정이 동시에 실행되는 경우에도 같은 순서로 처리한다.

낙관적 락은 충돌 후 다시 시도하는 처리가 필요하다.
이번 구현에서는 별도 버전 컬럼이나 재시도 없이 순서대로 처리할 수 있는
비관적 락을 선택했다. 대신 같은 세미나의 변경 요청에는 대기가 발생한다.

트랜잭션만으로는 조회와 저장 사이에 다른 요청이 실행되는 것을
막을 수 없으므로 락을 함께 사용한다.

### UNIQUE 제약조건

enrollments의 (rookieId, seminarId) UNIQUE 제약조건으로
같은 사용자의 중복 신청을 DB에서도 막는다.

이 제약조건은 기존 V1 Migration에 있으므로 다시 추가하지 않는다.
출석·과제 기록의 중복은 V4 Migration의
(enrollmentId, sessionId) UNIQUE 인덱스로 막는다.
기존 Migration은 수정하지 않는다.

### 취소의 삭제 건수 확인

취소는 신청을 실제로 삭제하는 구조이므로 조건부 DELETE를 사용한다.
삭제된 행이 한 개일 때만 성공으로 처리하고, 없으면 404를 반환한다.

별도 인원 컬럼은 두지 않고 실제 수강 신청 수를 조회한다.
따라서 신청과 다른 집계 값을 따로 관리할 필요가 없다.

## 트랜잭션 경계

수강 신청은 세미나 락 획득부터 중복·기간·정원 확인과 신청 저장까지를
하나의 트랜잭션으로 처리한다.

수강 취소는 세미나 락 획득, 연결된 출석·과제 기록 삭제,
수강 신청 삭제를 하나의 트랜잭션으로 처리한다.
중간에 실패하면 앞에서 삭제한 기록도 복원된다.

수강 정보 수정은 검증을 모두 마친 뒤 잔여 Grace Day와 탈락 여부를
함께 저장한다. 생략한 필드는 유지하며 신청 ID와 신청 시각은 변경하지 않는다.

출석·과제 일괄 수정은 요청에 포함된 모든 기록의 생성·수정·삭제를
하나의 트랜잭션으로 처리한다.
RuntimeException이 발생하면 이전 변경도 함께 롤백한다.

## 테스트

공통 ApiIntegrationTest의 Testcontainers 설정을 사용하여
실제 MySQL에서 확인한다.

추가한 테스트는 다음과 같다.

- team/TeamEnrollmentUpdateApiTest.kt
  - 부분 수정과 동일 값 재요청
  - Grace Day의 0과 최대값
  - null, 잘못된 타입, 범위 초과
  - 수정 권한과 다른 세미나의 신청 접근
  - 신청 정보와 기존 출석·과제 기록 보존
- team/ParticipationRollbackIntegrationTest.kt
  - 실제 첫 저장 이후 두 번째 저장 실패
  - 롤백 전 DB에서 변경된 값을 읽어 첫 쓰기가 실행된 것을 확인
  - 서비스 호출 종료 후 새 트랜잭션에서 모든 기록이 원래 값인지 확인

롤백 테스트의 저장소는 실제 저장소에 작업을 위임한다.
첫 저장은 실제로 실행하고 두 번째 저장 직전에 테스트 예외를 발생시킨다.
운영 API에는 실패를 발생시키는 기능을 추가하지 않는다.

동시성 테스트에서는 다음 결과를 확인한다.

| 상황 | 기대 결과 |
| --- | --- |
| 정원 30명에 100명 신청 | 201 30건, 409 70건 |
| 같은 사용자의 20회 신청 | 201 1건, 409 19건 |
| 같은 신청의 10회 취소 | 204 1건, 404 9건 |
| 신청과 취소 혼합 | 초기 인원 + 신청 성공 수 - 취소 성공 수 = 최종 인원 |

Docker를 실행한 뒤 다음 명령으로 테스트한다.

```bash
./gradlew test
```

이번에 추가한 테스트만 실행하려면 다음 명령을 사용한다.

```bash
./gradlew test --tests "com.wafflestudio.spring2026.team.*"
```

실행 결과는 위 명령으로 확인한 뒤 기록한다.
이 문서의 기대 결과를 실제 통과 결과로 대신하지 않는다.
